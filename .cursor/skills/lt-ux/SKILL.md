# local-tools · 体验 / 前端（UX）

## 原则

- 沿用现有 `styles.css` 与 dropzone 模式，避免每工具一套 UI
- 批量是**交互范式变更**：多选、进度、失败项列表、zip 下载一次讲清楚
- 暗色模式与拖拽改进是体验债，不得排在阻塞性元功能之前冒充「大版本」

## 评审焦点

- 新工具是否加剧首页卡片噪音？是否该分组/搜索？
- CLI / exe 是否与 Web UI 能力对齐（同一套转换逻辑）？
- 错误文案是否可行动（缺 LibreOffice 等）？

```markdown
## UX 意见
### 体验收益高
### 易做成半成品的交互
### 信息架构风险
### 建议的交互验收标准（AC）
```

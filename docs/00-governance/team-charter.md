# local-tools 虚拟研发团队编制

> 生效日期：2026-10-24（修订：补齐开发执行岗）  
> 产品：local-tools（本地优先 Web 工具集）  
> 总负责人：项目办 · 项目总经理（GM）  
> **编制人数：9**（虚拟角色；产品所有者不计入编制）

## 1. 团队使命

在「本地优先、文件不出本机、可赞助微收费」约束下，用有限带宽（约 10h/周）交付**可验证价值**的工具与元功能，避免工具箱膨胀成不可维护的功能堆。

## 2. 角色编制

合计 **9 个成员**：管理 / 专业岗 6 人（GM、PM、RD、UX、SEC、GTM）+ 开发执行岗 3 人（BE、FE、QA）。  
产品所有者不坐这些岗；GM 向产品所有者汇报。

### 2.1 管理 / 专业岗

| 代号 | 角色 | Skill 路径 | 职责边界 |
|------|------|------------|----------|
| **GM** | 项目总经理 / 总负责人 | `.cursor/skills/lt-gm/` | 拍板优先级、仲裁冲突、对外口径、里程碑验收 |
| **PM** | 产品经理 | `.cursor/skills/lt-pm/` + `pm-requirements` | 需求合理性、用户场景、优先级、非目标 |
| **RD** | 研发总监 | `.cursor/skills/lt-rd/` | 架构、可行性、ADR、技术拍板（**不替代写业务代码**） |
| **UX** | 体验设计 | `.cursor/skills/lt-ux/` | 交互范式、信息架构、验收标准（AC） |
| **SEC** | 隐私与安全 | `.cursor/skills/lt-security/` | 威胁模型、隐私话术边界、安全验收项 |
| **GTM** | 增长 / 出海叙事 | `.cursor/skills/lt-gtm/` + `go-to-market` | ICP、差异化话术、赞助解锁包装 |

### 2.2 开发执行岗（本轮补齐）

| 代号 | 角色 | Skill 路径 | 职责边界 |
|------|------|------------|----------|
| **BE** | 后端工程师 | `.cursor/skills/lt-be/` | FastAPI、`app/*.py`、BatchJob、CLI、依赖与清理 |
| **FE** | 前端工程师 | `.cursor/skills/lt-fe/` | `static/*`、批量 UI、接 API、首页卡片 |
| **QA** | 测试工程师 | `.cursor/skills/lt-qa/` | 冒烟/边界/回归；未过 P0 不建议验收 |

> **为何原先没有？** 首轮只搭了「评审班子」（定方向），未搭「施工队」。RD/UX 是设计与拍板，**不能代替 BE/FE 写代码与联调**。现已补齐。

### 2.3 协作关系（简图）

```text
GM ── 拍板 / 验收
 ├── PM / GTM / SEC ── 做什么、怎么说
 ├── RD / UX ──────── 怎么做、交互成什么样
 └── BE + FE ──────── 落地代码
      └── QA ──────── 验证后回 GM
```

## 3. 决策规则

1. **市场问题 → 需求 → 方案 → 实现**：PM 写场景；RD 出 ADR；BE/FE 按 ADR 开工；QA 验收；GM 签字。
2. **元功能优先于单工具**。
3. **依赖预算**：核心路径不得强制大模型；可选插件单独声明。
4. **赞助解锁**：仅大批量 / 高级水印 / 超大文件；不锁基础隐私能力。
5. **冲突升级**：专业岗争执 → GM；实现与设计不符 → RD/UX 当场裁决或升级 GM。
6. **文档与功能同发**：见第 6 节。没跟上的必要文档 = 该模块未交付。

## 4. 协作仪式

| 仪式 | 触发 | 产出 |
|------|------|------|
| 需求评审会 | 新路线图 / 大 backlog | `docs/00-governance/` 纪要 |

| 文档对账 | 每个功能模块落地时 | 同一次改动更新对应分册 |

## 6. 文档同步责任制（2026-10-25 · GM 指定）

**这件事的总负责人是 PM。** 每个功能模块开发时，必要文档必须跟着改；PM 对「写没写全、跟没跟上行为」签字负责。QA 未见到对应文档不得建议验收；GM 未见到文档不得宣布交付。

### 6.1 谁写什么（同一次改动里完成）

| 文档 | 执笔 | 何时必须改 |
|---|---|---|
| `README.md` 功能表 / 项目结构 | BE 或 FE（谁加的入口） | 新工具、新 CLI 子命令、新限制 |
| `docs/01-product/` 说明书 | **PM** 定稿；BE/FE 先补草案 | 用户能感知的行为变了 |
| `docs/03-engineering/ADR-*` | **RD** | 新依赖、新架构分叉、共用管线 |
| `docs/04-testing/` 冒烟 / 回归 | **QA** | 新主路径、新边界 |
| `docs/local-tools-roadmap.md` 状态表 | **PM** | 里程碑状态变化 |
| `docs/00-governance/wiki.md` 索引 | **PM** | 新增长期文档 |
| 隐私 / 赞助话术 | **SEC** / **GTM** | 对外怎么说变了 |
| 交互 AC | **UX** | 页面流程变了 |

**谁改代码，谁先改自己那一栏的草案**，不得甩给「回头再写」。PM 收口并核对有无漏册。

### 6.2 最低必要文档（新模块未齐 = 未交付）

1. README 或说明书里能找到入口  
2. 路线图状态已改  
3. 至少 1 条 P0 冒烟写进 `docs/04-testing/`  
4. 有架构分叉则必须有 ADR  

Wiki 是入口，不替代上述分册。

## 7. 员工 Agent SKILL 沉淀（2026-10-25 · GM 指定）

开发过程中**多次**把验证过的角色做法写成 skill，不等项目结束。全局技能：`docs-with-features`、`precipitate-role-skill`（`~/.cursor/skills/`）。本仓角色仍写 `.cursor/skills/lt-*`，只写覆盖项。

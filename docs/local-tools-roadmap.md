# local-tools 功能路线图（2026-10-24）

> 定位：local-tools 是产品所有者「本地优先 Web 工具集」（FastAPI + 浏览器 UI，内置 ffmpeg，文件不出本机）。  
> 本文汇总功能建议与落地顺序。  
> **2026-10-24 修订**：已按 GM 团队评审收敛 MVP、话术与状态表（见 `docs/00-governance/roadmap-review-2026-10-24.md`）。  
> 现状：已有 8 个工具 —— 视频转音频 / 视频压缩 / 图片压缩 / 图片转换 / JSON 格式化 / Base64 编解码 / CSV↔Excel / 文档转换。

---

## 一、最高杠杆：元功能（做一次，所有工具一起升值）

> 现状最大短板是「单文件处理」「不能脚本化」「分发麻烦」。元功能优先级高于单个新工具。

| 元功能 | 价值 | 工作量 | 优先级 | 说明 |
|---|---|---|---|---|
| 批量处理 + 打包 zip 下载 | ★★★★★ | 中 | **P0** | 图片/文档等多选 → zip。产品化最大单点提升。设计见 ADR-001 |
| 国际化（i18n） | ★★★★ | 中 | **P1** | 先于 CLI；Web 文案 + 接口错误；首刀 zh / en |
| CLI 模式 | ★★★★ | 中 | **P1** | 与 Web 共用 handler；排在 i18n 之后 |
| 便携单文件 exe | ★★★★ | 中 | **推迟** | CLI 已证明。2026-10-26 评估后仍不打包，形态见 ADR-004 |
| 本地历史（IndexedDB，不上云） | ★★★ | 小 | P3 | 2026-10-26 首刀已落地：首页最近处理 + 本机保存 20 条 + 可清空 |
| 暗色模式 + 拖拽改进 | ★★ | 小 | P3 | 体验小修 |

## 二、新工具建议（按需求 × 成本排序）

### 🟢 第一梯队：复用现有依赖、几乎零额外成本、需求硬

- **PDF 合并 / 拆分 / 旋转 / 提取页** —— PyMuPDF；**MVP：先合并+压缩，拆分可同迭代**
- **PDF 压缩** —— PyMuPDF 重采样 + 垃圾回收
- **PDF 加密 / 解密 / 加权限** —— 合同发票保护；**P1**（话术见第三节，勿称「跨境合规」）
- **图片 EXIF 查看/清除** —— 发布前抹 GPS/设备信息；**P0，必须免费**
- **图片批量水印（文字/平铺）** —— 防盗图/店名；**P2**，可作赞助高级项；MVP 不强制
- **CSV 清洗 / 去重 / 筛选** —— **P2**（已落地基础刀：去空行、精确去重、留列；透视/公式不做）

### 🟡 第二梯队：内容/广告相关（FFmpeg 或 Pillow）· 滚动排期

- 视频转 GIF、提取封面帧、视频裁剪/截取
- 视频/图片加水印、字幕烧录
- 九宫格切图 / 图片拼接
- 二维码生成 + 识别  

> 勿写入对外主 Slogan，直至落地。

### 🔵 第三梯队：开发者小工具 · **大量推迟**

- JSON ↔ YAML / TOML、Markdown ↔ HTML、哈希/重复文件、正则/Diff 等  
> 首页先分组/搜索再考虑加卡片，避免工具箱噪音。

### ⚪ 高价值但依赖重（可选装，别放核心）

- **图片去背景（rembg）** —— optional-dependencies，不进默认安装与首屏

## 三、对外叙事（GTM · 已收敛话术）

**对外怎么说：** 商品图和 PDF 在本机批量处理，文件不上传。

发布形态：开源仓库（AGPL-3.0）、源码自跑。不收费、不做免安装承诺。见 `LICENSE`、ADR-005。

可强调（须已落地或当期交付）：

- 发布前 **EXIF 清除**（有助于隐私控制，**非法律/合规认证**）
- PDF 发票/合同 **压缩 / 加密**（本地自控）
- **批量 + zip**（本机处理）
- 水印防盗图（高级项可赞助）

跨境卖家是**叙事切口**，不是唯一用户；勿把产品锁成「仅跨境插件」。

**赞助解锁边界：** 大批量、超大文件、水印高级项。  
**禁止赞助锁定：** 基础 EXIF 清除、基础大小限制与安全清理。

## 四、MVP 落地顺序（契合 10h/周 · GM 裁决）

1. **批量 + zip** —— 让现有工具立刻变实用（ADR-001）
2. **PDF：合并 + 压缩**（拆分可同迭代；加密已在 CLI 之后落地）
3. **图片 EXIF 清除**（免费）
4. **国际化（i18n）** —— Web 界面与错误文案，先于 CLI
5. **CLI 模式** —— 映射已有 handler
6. **基础文字水印** —— 已落地；2026-10-26 补斜向平铺
7. **CSV 清洗** —— 去空行 / 去重 / 留列；Web + CLI
8. **CLI 补视频** —— 转音频 + 压缩；与网页同一套函数
9. **便携 exe 评估** —— 结论：继续推迟。形态见 ADR-004，不产出安装包
10. **本地历史首刀** —— 首页最近处理；只记本机摘要，不存文件内容

## 五、加一个新工具的固定套路

1. 写 `app/xxx.py` 处理函式（能进批量则接入 `run_batch`）
2. `main.py` 加路由（带大小限制 + try/except → `FileResponse` + `BackgroundTask(_cleanup)`）
3. 新增 `static/xxx.html` + `static/xxx.js`（vanilla JS，沿用 `styles.css`）
4. `static/index.html` 加 `tool-card`（卡片过多时先分组）
5. **同一次改动**更新必要文档（README、说明书、路线图状态、测试 P0；有分叉则 ADR）。总责 **PM**
6. QA 勾 P0 **且**核文档后再请 GM 验收

**分工：** BE 做 1–2 及后端相关文档草案；FE 做 3–4 及页面相关文档草案；PM 收口第 5；QA 做 6。未齐文档 = 模块未交付。见 `docs/00-governance/team-charter.md` 第 6 节。
